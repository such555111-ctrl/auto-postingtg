# Telegram-бот автопостинга по брендам

Бот собирает новые посты из исходного канала, определяет бренд каждого поста и по расписанию,
которое вы настраиваете прямо в боте, публикует выбранные бренды в целевой канал.

Стек: Python 3.10+ (на Render — 3.12), aiogram 3, PostgreSQL (asyncpg) на хостинге / SQLite локально.

---

## 1. Как это работает (архитектура)

```
Исходный канал ──channel_post──▶ collector ──▶ SQLite (posts, post_messages)
                                     │                    ▲
                              определение бренда          │ пул постов
                              (brands.py: алиасы)         │
                                                          │
Админ ◀──▶ меню/мастер (aiogram, FSM) ──▶ schedules ──▶ Scheduler (цикл раз в 10 с)
                                                          │ copyMessages
                                                          ▼
                                                   Целевой канал
```

* **Сбор.** Бот — администратор исходного канала, поэтому Telegram присылает ему `channel_post`.
  Альбом (как в ваших постах: несколько фото/видео + подпись) приходит отдельными сообщениями с общим
  `media_group_id` — бот склеивает их в **один пост**. Сохраняются: текст/подпись, тип и `file_id` каждого
  медиа, дата (UTC и «локальный день»), ссылка на оригинал, бренд. Правки поста в канале тоже подхватываются.
* **Бренд.** Ищется по названию и алиасам с границами слов. Бренд из **заголовка** (первая строка:
  `🅒 CHANEL 🅒`, `CHOPARD`) весит больше, чем упоминания в тексте — поэтому пост Chopard со
  «кристаллами Swarovski» определяется как Chopard. Не нашли ничего — «не определён» (можно назначить
  вручную). Алиас `шанел*` ловит любые окончания (шанель, шанели…).
* **Публикация.** Через `copyMessages`: альбом остаётся альбомом, подпись, цитата-блок «Шикарный комплект…»,
  цены и ссылки сохраняются как есть, пометки «Переслано» нет.
* **Расписание.** Это набор слотов: `начало, начало+интервал, … ≤ конец`. В момент слота берётся
  следующий пост из пула (посты за день, выбранные бренды, ещё не опубликованные). Пул динамический:
  посты, пришедшие в канал уже во время окна, тоже попадут в очередь.
* **Надёжность.** Всё состояние в базе данных — после перезапуска расписания и посты на месте.
  Пост **резервируется до отправки** (`UNIQUE(schedule_id, post_id)`), поэтому дубль невозможен даже при сбое
  посреди отправки. Ошибки Telegram: FloodWait — ждём и повторяем; сетевые/5xx — повтор на следующем
  проходе; «нет прав» — расписание ставится на паузу и админы получают уведомление; отклонённый пост
  помечается `failed`, и в этом же слоте берётся следующий.

## 2. Файлы проекта (всё лежит в одной папке, без подпапок)


> скрыты в проводнике — не забудьте закинуть их на GitHub (`.python-version` и `render.yaml` нужны Render).

## 3. Создание бота и доступ к каналам

1. В Telegram откройте **@BotFather** → `/newbot` → имя и username → получите **токен**.
2. **Исходный канал**: Управление каналом → Администраторы → Добавить администратора → ваш бот.
   Достаточно минимальных прав (бот только читает). Без прав администратора Telegram **не присылает**
   боту посты канала.
3. **Целевой канал**: добавьте бота администратором с правом **«Публикация сообщений»**.
4. Свой Telegram ID: запустите бота и напишите `/start` с любого аккаунта — если вас нет в `ADMIN_IDS`,
   бот ответит «Нет доступа» и покажет ваш ID.
5. ID канала (`-100…`) можно не искать вручную: в боте «Настройки каналов» → перешлите любой пост из канала.

## 4. Запуск на бесплатном Render

**Что важно знать про бесплатный Render** (поэтому в проект добавлено три вещи):

| Особенность Render Free | Что сделано |
|---|---|
| Web Service обязан слушать порт | `main.py` поднимает мини-сервер на `$PORT` (`/` и `/health`) |
| Засыпает через 15 минут без входящих запросов | Бот пингует сам себя каждые 10 минут + внешний пингер (шаг 5) |
| Диск стирается при каждом перезапуске/деплое/засыпании — **SQLite-файл не сохранится** | Данные хранятся во внешнем Postgres через `DATABASE_URL` |
| Бесплатный Postgres **на самом Render живёт 30 дней** и затем удаляется | Используем бесплатный Postgres у Supabase (или Neon) |

### Шаг 1. База данных (Supabase)

1. Зарегистрируйтесь на supabase.com → **New project** (придумайте пароль БД и сохраните его).
2. Нажмите **Connect** вверху проекта → выберите **Session pooler** (работает по IPv4) и скопируйте строку вида
   `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-….pooler.supabase.com:5432/postgres`.
3. Вместо `[YOUR-PASSWORD]` подставьте пароль. Если в пароле есть спецсимволы (`@ : / # ?`) — закодируйте их
   (`@` → `%40`) или поменяйте пароль на буквы и цифры.

Таблицы бот создаст сам при первом запуске. Подойдёт и Neon (neon.tech) — берите обычную строку подключения;
но Neon «засыпает» при простое, а бот обращается к базе каждые 10 секунд, поэтому бесплатные часы Neon могут
уходить быстрее — Supabase для этого бота удобнее.

### Шаг 2. GitHub

Создайте репозиторий и загрузите **все файлы из папки как есть** (в корень репозитория, без вложенных папок).
Файл `.env` с токеном на GitHub загружать **не нужно** — токен вводится в Render.

### Шаг 3. Сервис на Render

Вариант А (проще): **New + → Blueprint** → выберите репозиторий — Render прочитает `render.yaml` и спросит значения
`BOT_TOKEN`, `ADMIN_IDS`, `DATABASE_URL`.

Вариант Б (вручную): **New + → Web Service** → репозиторий, затем:

* Runtime: **Python 3**; Build Command: `pip install -r requirements.txt`; Start Command: `python main.py`
* Instance Type: **Free**; Health Check Path: `/health`
* Environment: `BOT_TOKEN`, `ADMIN_IDS`, `DATABASE_URL`, `PYTHON_VERSION=3.12.8`, `TIMEZONE=Europe/Moscow`, `LOG_FILE=` (пусто)

После деплоя в логах Render должно появиться «Бот запущен: @…» и «База данных: postgres». Напишите боту `/start`.
Каналы (`SOURCE_CHANNEL_ID` / `TARGET_CHANNEL_ID`) можно задать в самом боте: «Настройки каналов» — они сохранятся в базе.

### Шаг 4. Не давать сервису засыпать (рекомендуется)

Самопинг работает, пока сервис бодрствует, но если Render его всё же усыпил или перезапустил, будить его должен
кто-то снаружи. Зарегистрируйтесь на uptimerobot.com (бесплатно) → **Add New Monitor** → тип **HTTP(s)**,
URL: `https://<имя-вашего-сервиса>.onrender.com/health`, интервал **5 минут**.

### Ограничения и нюансы

* Бесплатных часов Render — 750 в месяц на аккаунт: хватает на **один** сервис, работающий круглосуточно.
* Render может перезапустить бесплатный сервис в любой момент. Расписания и посты при этом не теряются (они в Postgres),
  а слоты, которые пришлись на время простоя дольше `MISSED_GRACE_MINUTES` (10 мин), помечаются «пропущен».
* При деплое новой версии на несколько секунд могут работать две копии бота — в логах мелькнёт «Conflict», это нормально.
* Посты, пришедшие пока бот спал, Telegram сохраняет и доставляет при пробуждении (до ~24 часов), но лучше не давать боту спать.
* Бот обращается к Telegram через long polling; webhook, если был, при старте удаляется.

### Локальный запуск (без Render)

```bash
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # заполните BOT_TOKEN и ADMIN_IDS; DATABASE_URL можно не трогать
python main.py
```

Без `DATABASE_URL` данные лежат в `data/bot.db` (SQLite), логи — в `logs/bot.log`.

## 5. Сценарии использования

Главное меню (кнопки):

| Кнопка | Что делает |
|---|---|
| **Настроить автопостинг** | Мастер из 5 шагов: бренды → дата → начало → конец → интервал → порядок → подтверждение |
| **Сегодняшние бренды и посты** | Бренды с количеством постов за сегодня; по клику — список постов со ссылками; 🏷 — ручное назначение бренда |
| **Активные расписания** | Статус, окно, прогресс (отправлено из слотов), размер очереди; «Остановить»/«Возобновить» |
| **Остановить автопостинг** | Остановить одно расписание или все сразу |
| **Бренды и алиасы** | Добавить/переименовать/удалить бренд, заменить или дополнить алиасы, пересчитать бренды у постов |
| **Настройки каналов** | Указать исходный/целевой канал (пересылкой поста, ID или @username), проверить права бота |

Команды: `/start`, `/menu` — меню; `/cancel` — отмена текущего шага.

**Типовой день:**
1. В течение дня бот копит посты. «Сегодняшние бренды и посты» → видите `Chanel — 3`, `Chopard — 2`, `Не определён — 1`.
2. Нераспознанный пост: 🏷 → выбрать бренд (или добавить алиас в «Бренды и алиасы» — бренды пересчитаются сами).
3. «Настроить автопостинг» → отметьте бренды → дата (кнопка «Сегодня»/«Завтра») → `10:00` → `18:00` → `15` →
   порядок. На экране подтверждения видно: сколько постов доступно, сколько слотов, сколько будет
   опубликовано и что не поместится. «✅ Запустить».
4. По окончании окна админы получают итог: опубликовано / пропущено / пустых слотов / ошибок.

**Порядок выбора постов:** *по времени* (старые первыми), *случайный*, *по очереди* (бренды чередуются:
Chanel → Chopard → Chanel…; если у бренда посты кончились, он пропускается).

## 6. Тестирование

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

* `test_brands.py` — определение бренда на текстах ваших постов (Chanel; Chopard с упоминанием Swarovski;
  «не определён»; окончания; границы слов; приоритет заголовка).
* `test_planner.py` — разбор даты/времени, слоты окна, порядок выбора (в т.ч. round-robin).
* `test_db.py` — слой БД: бренды/алиасы, дубли, резервирование постов, преобразование для Postgres.
* `test_scheduler.py` — расписание целиком на SQLite в памяти и поддельном боте:
  альбом копируется целиком, дублей нет, пропущенные слоты после простоя, отклонённый пост → следующий
  в том же слоте, один пост не публикуется дважды в разных расписаниях, продолжение после «перезапуска».

Ручная проверка в Telegram: добавьте бота в оба канала, опубликуйте в исходном тестовый пост
(`CHANEL …`), откройте «Сегодняшние бренды и посты», запустите расписание на ближайшие 2–3 минуты с
интервалом 1 мин и убедитесь, что пост появился в целевом канале.

## 7. Важные ограничения Telegram и история канала

* Bot API **не позволяет читать историю канала** до момента, когда бот получил доступ. Бот сохраняет
  **только новые посты** с этого момента. «Посты за сегодня» — это только те, что бот успел сохранить;
  всё, что вышло раньше, он не увидит.
* Для загрузки старых постов нужна отдельная загрузка истории (например, через пользовательский аккаунт и
  библиотеку Telethon). **В этот проект такой способ не добавлен** и не обещан: он требует входа под
  личным аккаунтом (api_id/api_hash, сессия), нарушает «ботовую» модель доступа, может привести к
  ограничениям аккаунта и хранит секретную сессию. Если решите добавить — это отдельная доработка с
  явной настройкой; готов описать её отдельно.
* `copyMessages` копирует только сообщения, которые ещё существуют в исходном канале. Если пост удалён —
  Telegram его пропустит, бот пометит пост `failed`, возьмёт следующий и предупредит админов.
* Бот работает через long polling. Если у бота настроен webhook, при старте он будет удалён.

## 8. Неоднозначности и принятые решения

| Вопрос | Решение по умолчанию |
|---|---|
| Что такое «пост» | Одно сообщение **или целый альбом** (так выглядят ваши посты). Публикуется целиком |
| «Сегодня» | В часовом поясе `TIMEZONE` (по умолчанию Europe/Moscow) |
| Дата публикаций vs дата постов | Посты берутся за **сегодня** (на момент запуска мастера), публиковать можно сегодня или позже («Завтра») |
| Интервал vs «равномерно» | Слоты идут с шагом интервала внутри окна. Если постов меньше слотов — лишние слоты пустые; бот подсказывает интервал, который растянет посты на всё окно. Если постов больше — лишние не поместятся (об этом предупреждает экран подтверждения) |
| Бренд из заголовка vs из текста | Заголовок (первая строка) приоритетнее; при равенстве — тот, что встретился раньше |
| Опоздавший слот (бот был выключен) | Если опоздание > `MISSED_GRACE_MINUTES` (10), слот пропускается, а не публикуется с опозданием |
| Один пост в нескольких расписаниях | Не повторяется (`ALLOW_REPOST_ACROSS_SCHEDULES=true` разрешает повтор между разными расписаниями; внутри одного — никогда) |
| Ручной бренд | Назначенный вручную бренд не перезаписывается автоопределением и пересчётом |
| Стартовые бренды | При первом запуске создаётся набор (Chanel, Chopard, Cartier, Van Cleef & Arpels, Bvlgari, Tiffany, Dior, Gucci, Louis Vuitton, Hermes, Swarovski, Pandora) — правится в боте |
| Состояние мастера | Хранится в памяти: при перезапуске незаконченная настройка сбросится, **сохранённые расписания — нет** |
| Доступ | Только `ADMIN_IDS`; остальным бот отвечает «Нет доступа» с их ID |

## 9. Логи

В консоли (на Render — вкладка **Logs**) и, если задан `LOG_FILE`, в `logs/bot.log` (ротация 5 МБ × 5). Действия администраторов пишутся логгером `admin`
(каждое сообщение и нажатие кнопки с ID админа), ошибки Telegram API и планировщика — с трассировкой.
